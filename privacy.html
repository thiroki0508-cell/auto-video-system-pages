Privacy Policy

How the desktop application and this separate documentation website handle information.

Policy version: 2026-10-14.2

Effective and last updated: October 14, 2026

1. Scope and operator

Auto Video System is a private Windows desktop application developed and used by an individual developer in Japan for personal research and original-content planning. It is not a public web service. This website provides information and policies; it does not offer the desktop application's features or receive its local databases.

The app uses YouTube API Services. Google's handling of requests is described in the Google Privacy Policy. The YouTube Terms of Service also apply.

2. Information accessed and stored locally

  • Public YouTube information: video IDs and URLs, titles, channel names, thumbnail URLs, publication dates, durations, view counts, and retrieval timestamps. Limited public descriptions can be fetched when the optional description check is selected.
  • Research settings and records: search keywords, date/order/result settings, genre-rotation state, kept/pending status, personal review notes, video-linked analysis and manual review records. A separate local consent record stores agreement status, UTC agreement time, policy version, content hash, and policy URL.
  • Personal planning inputs: the owner's production assumptions, fees, working time, labor rates, and, if used, original-topic drafts and generated planning outputs.
  • Operational information: local API call timestamps, endpoint names, estimated usage, success/error categories, and separate optional OpenAI request and cost records.

These records are stored in local settings files and SQLite databases on the owner's computer. The databases and ordinary settings are not encrypted by the app. Public metadata may itself contain creators' names or other personal information. The app does not request YouTube passwords, private account data, contacts, or location permissions.

3. Purpose and sharing

Information is used to search and display public videos, organize candidates, support manual review and limited local rule-based analysis, and consider the owner's own production plans. Operational records support usage limits and troubleshooting. Metadata is not evidence of a creator's earnings, production costs, or consent to reuse their work.

The desktop app has no developer-operated collection server and does not automatically publish its research databases. It does not sell local research data. Nevertheless, the external requests described below send information to service providers. Local files can also be accessed by people or software with access to the computer or its backups. Avoid entering private information in searches, notes, or original topics.

4. API keys and security

The YouTube API key and optional OpenAI API key are stored separately using Windows Data Protection API (DPAPI), bound to the current Windows user. Keys are decrypted in memory for requests and sent in HTTPS request headers, not embedded in request URLs. This protects the key files; it does not encrypt the entire app or protect against all access by software running as the same user.

YouTube API usage/error records are designed to exclude keys, raw request URLs, and full API responses. Optional OpenAI response storage is separate and described below. The owner remains responsible for the computer's security, backups, and provider-side key restrictions.

5. Retention, refresh, and deletion

Pending video candidates
Default: 7 days from first discovery. The owner can set 1–30 days. The general metadata limit below also applies.
All stored YouTube metadata, including kept candidates
At most 30 days from the record's latest fetch in the active database. Search can refresh a record; otherwise expiry cleanup deletes it. Keeping a candidate does not exempt it from expiry. Stored descriptions also expire after 30 days and are deleted with the associated video if that happens sooner.
Video-linked notes and local analysis
Removed with the associated candidate when it is discarded or expires. A manual review record is not an independently retained copy of the video metadata.
Thumbnail images
Downloaded for display or local image checks and held in memory; the app does not maintain a persistent thumbnail image cache.
Independent planning settings and original projects
Owner-entered production assumptions, separately saved original-topic projects/exports, and the local privacy consent record are retained until the owner deletes them. They are not subject to the YouTube candidate expiry schedule.
Usage and error history
Local YouTube usage records and optional OpenAI cost records have no automatic age limit. Error log rotation is approximately 256 KB per file with two older generations. These operational records are separate from the video metadata database.

Video expiry cleanup runs on application startup, before searches, and periodically while the app is running. Description expiry is checked when local analysis runs. Nothing can be cleaned up while the application is stopped; overdue cleanup occurs when the relevant app or feature runs again. These are local cleanup rules, not continuous background deletion guarantees.

Some known diagnostic exports expire after 30 days. Manually created exports, screenshots, copies, and backup folders are not all covered by automatic cleanup. The owner must also refresh or delete any retained API-data copies within the applicable retention period.

6. Your controls

Use a video card's discard action to delete a candidate and its linked review/analysis records. A keep action changes the review state, not the retention limit. Searching again may refresh metadata for a returned video; it is not a continuous automatic refresh service.

The YouTube API/settings dialog includes a key deletion action. Removing a local key does not revoke it at Google; disable or delete it in the Google Cloud project if needed. There is currently no OpenAI key-deletion button. After closing the app, the owner can remove its separately encrypted OpenAI key file manually and revoke the key with OpenAI.

To remove all local app data, first close the application, then remove the app-owned settings/key files, databases, exports, logs, and any copies or backups from its configuration, data, and log folders. This resets local information; it does not delete videos or any other information stored by YouTube or records held by external providers.

The app currently has no YouTube OAuth grant to revoke. Any Google account permissions can be reviewed at Google's third-party access settings. This is separate from API-key management.

7. Connections to Google and YouTube

Search requests send the search query, publication-date cutoff, sort order, result/page parameters, and API key to Google's YouTube API. Video-detail requests send video IDs and requested metadata fields. Thumbnail requests go to Google/YouTube image servers and identify the requested image. These services receive ordinary network information such as IP address and request timing.

Thumbnail images are third-party content. The app does not embed a video player, serve ads, or include an analytics SDK. Clicking a YouTube link opens the browser, where YouTube's own privacy practices, cookies, and account settings apply. The desktop app itself does not implement cookie-based tracking.

8. Optional OpenAI original-topic planner

A separate developing feature can use a separately registered OpenAI API key. A connection check retrieves the available model list. When the owner explicitly requests an original-topic plan, the app sends the entered topic, general planning instructions, schema, and generation settings to OpenAI's Responses API. The current planner does not read or attach the app's YouTube video database. Do not paste YouTube API data, secrets, or personal information into this input.

Requests set store: false. This is a request option, not a guarantee of zero retention by OpenAI. Provider-side processing is governed by applicable OpenAI terms and data policies; see OpenAI's Privacy Policy. OpenAI receives request and network information, and API use may incur charges on the owner's account.

Original topics, validated planning drafts, and adoption states can be stored locally in a separate project database and exported locally. Raw API responses are also stored in a separate local request ledger; response bodies older than 30 days are cleared when the AI workspace/settings or generation request invokes cleanup. Cost, token, request-fingerprint, and safe-error records remain until manually deleted. Saved original projects and exports are not erased by that response-cache cleanup. No automatic publication occurs.

9. This website and contact

This static site is hosted by GitHub Pages. It contains no developer-added analytics, advertising, external fonts, tracking scripts, forms, or cookie storage. GitHub processes hosting requests and may record IP addresses and other request information under the GitHub General Privacy Statement. Following an external link connects you to that site's provider.

For general questions or privacy concerns, contact the maintainer through this documentation repository's GitHub Issues. Issues are public. Post only a general description; never submit keys, account details, private files, or personal information. Posting requires a GitHub account and is subject to GitHub's policies. Local app data is under the owner's control; use the local deletion steps above rather than uploading it to request deletion.

10. Policy updates and current limitations

Revisions appear on this page with a policy version and effective date; the public documentation repository records changes. An app release that changes this policy updates its bundled version and the SHA-256 hash of this published HTML document. A missing, malformed, or outdated agreement record requires renewed agreement before external features can be used. Changes to data access, purpose, sharing, retention, or deletion require a new version and renewed agreement. The current build also requires renewed agreement whenever its bundled policy hash changes. The app does not automatically download or discover website revisions: the maintainer must update the bundled policy manifest and release the corresponding app update together with a policy revision. This website does not provide automated update notifications.

The desktop app presents an agreement screen before first use when no valid record exists. It links to this public policy, the YouTube Terms of Service, and the Google Privacy Policy. Only an explicit Agree action saves the local record; refusal or closing the screen exits without starting external features or deleting existing keys or databases. A valid current record permits normal startup. The YouTube API client also checks the current local agreement before each real API request. The app information dialog provides access to this public policy during normal use. A local agreement is not YouTube OAuth authorization and does not establish approval by Google or YouTube.
